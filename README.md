# Dictation Lab

받아쓰기로 영어 청취 취약점을 진단하는 학습 사이트. 빌드 도구도 서버도 없이 정적 파일로 동작한다.

## 왜 딕테이션인가

| 목적 | 이 사이트에서의 구현 |
| --- | --- |
| **연음 파악** | 0.6× / 0.8× / 1.0× 배속 재생, 무제한 반복 청취, 채점 후 문장별 연음·축약 해설(어떤 자음이 어디로 넘어가 무슨 소리가 되는지) |
| **취약점 개선** | 단어 단위 정렬 채점 → 틀린 단어를 관사·전치사·축약형·시제·복수 등 9개 유형으로 자동 분류 → 누적 통계로 반복되는 약점을 수치화 |
| **스피킹 향상** | 정답 공개 후 섀도잉 녹음(MediaRecorder). 원음과 자기 발화를 번갈아 들으며 리듬 비교 |

기본 제공 5코스 40문장 외에, **유튜브 영상의 자막을 가져와 나만의 코스**를 만들 수 있다. 이쪽은 TTS가 아닌 실제 원어민 발화라 연음 연습에 훨씬 낫다.

## 실행

정적 파일이라 아무 HTTP 서버나 쓰면 된다. ES 모듈을 쓰므로 `file://` 로 직접 열면 안 된다.

```bash
python3 -m http.server 4173
# → http://localhost:4173
```

배포도 그대로 올리기만 하면 된다(GitHub Pages, Netlify, S3 등).

## 유튜브 자막으로 코스 만들기

홈 → **＋ 유튜브 자막 가져오기**.

1. 영상 주소를 붙여넣는다 (`watch?v=`, `youtu.be`, `/shorts/`, `/embed/`, `/live/` 모두 인식).
2. 자막을 넣는다. 둘 중 아무거나:
   - 유튜브 영상 아래 **더보기 → 스크립트 표시** 패널을 전체 복사해 붙여넣기
   - `.srt` / `.vtt` 자막 파일 열기 (`yt-dlp --write-auto-sub --skip-download` 등으로 받은 것)
3. 미리보기에서 필요 없는 문장(인트로, 광고 등)을 체크 해제하고 저장.

### 왜 붙여넣기인가

유튜브 자막 엔드포인트는 CORS 헤더를 주지 않아 **브라우저에서 직접 받아올 수 없다.** 자동으로 긁으려면 서버(프록시)가 필요하고 그건 유튜브 약관에도 어긋난다. 대신 자막은 사용자가 넣고, **재생은 공식 IFrame 임베드 플레이어**가 문장의 `[start, end]` 구간만 반복하게 했다. 영상을 내려받지 않으므로 약관 문제가 없고, 무엇보다 실제 원어민 음성을 그대로 쓴다.

받아쓰기 중에는 정답이 새지 않도록 자막 표시를 끄고(`cc_load_policy: 0`) 화면도 기본으로 가려 둔다. 발음 입 모양을 보고 싶으면 **영상 보기** 버튼으로 열 수 있다.

### 자막을 문장으로 합치는 방법

자막은 문장이 아니라 2~5단어 조각이라 그대로는 받아쓰기에 못 쓴다. `js/captions.js` 가 처리하는 것:

- **형식 자동 판별** — WebVTT / SubRip / 스크립트 패널 복사본
- **잡음 제거** — `[Music]`, `(laughs)`, `>>` 화자 표시, VTT 인라인 워드 타이밍 태그(`<00:00:03.100><c>`), HTML 엔티티
- **롤링 중복 제거** — 자동 생성 자막은 같은 줄이 스크롤되며 반복된다. 앞 큐의 꼬리와 겹치는 머리를 잘라낸다
- **문장 분할** — 문장부호가 있으면 `.!?` 기준. 자동 생성 자막처럼 **문장부호가 아예 없으면** 목표 단어 수를 넘긴 뒤 첫 큐 경계(≒ 화자의 호흡 지점)에서 끊는다
- **타이밍 보정** — 자막 시각은 실제 발화와 조금 어긋나므로 앞 0.25초·뒤 0.35초 여유를 준다

문장 길이는 짧게(7단어) / 보통(11) / 길게(16) 중에 고른다.

### 한계

- 가져온 코스에는 한국어 번역과 연음 해설이 없다 (기본 코스에만 있음). 정답 문장과 재생 구간만 표시된다.
- 자동 생성 자막은 받아쓰기 정답으로 삼기엔 오탈자가 있을 수 있다. 수동 자막이 있는 영상이 훨씬 정확하다.
- 같은 영상을 다시 가져오면 문장 id가 유지되어 학습 기록이 이어진다.

## 구조

```
index.html            화면 골격 + <template> 4종 (홈 / 연습 / 가져오기 / 통계)
css/style.css         라이트·다크 자동 전환
js/
  app.js              해시 라우팅, 화면 렌더링, 연습 세션 진행
  diff.js             토큰화 → 축약형 보정 → Needleman-Wunsch 정렬 → 채점
  analyze.js          정렬 결과를 문법/발음 카테고리로 분류
  captions.js         자막 파싱(VTT/SRT/스크립트 패널) → 정리 → 문장 분할
  youtube.js          IFrame 플레이어 래퍼 — [start, end] 구간만 재생
  audio.js            재생 엔진(Web Speech API / audio 파일) + 섀도잉 녹음
  store.js            localStorage 기록·통계 + 가져온 코스 저장
  data/lessons.js     기본 제공 학습 콘텐츠
```

### 채점이 동작하는 방식

1. **토큰화** — 대소문자·문장부호를 무시하되 아포스트로피는 남긴다. 표시용 원본과 비교용 정규형을 같은 인덱스로 유지해, 채점은 정규형으로 하고 화면에는 원문을 그대로 보여준다.
2. **축약형 보정** (`reconcileContractions`) — `I'm` 을 `I am` 으로, `going to` 를 `gonna` 로 쓰면 토큰 개수가 어긋나 정렬 전체가 밀린다. 정답 표기에 맞춰 입력 쪽을 쪼개거나 합친 뒤 정렬한다. 소리는 제대로 들은 것이므로 **감점하지 않고** "표기만 다름"으로만 안내한다.
3. **정렬** — 단어 단위 DP. 오타 수준의 근접 단어는 낮은 비용으로 짝지어 억지 매칭을 막는다.
4. **분류** — `del`/`ins`/`sub` 각각을 어휘 집합과 접미사 규칙(`-s`, `-ed`, 불규칙 과거형)으로 판정해 카테고리를 붙인다.
5. **집계** — 시도 로그를 원본 그대로 저장하고 통계는 읽을 때 계산한다. 분류 기준이 바뀌어도 과거 기록이 살아 있다.

## 콘텐츠 추가

`js/data/lessons.js` 에 문장을 추가하면 된다.

```js
{
  id: 'l1-9',                       // 전역 고유
  text: 'Take a look at this one.',  // 정답이자 TTS 낭독 원문
  ko: '이거 한번 봐봐.',
  audioUrl: 'audio/l1-9.mp3',        // (선택) 원어민 녹음. 없으면 TTS로 재생
  linking: [
    { span: 'Take a look at',        // text 안에 그대로 존재해야 하이라이트된다
      tip: "Ta-ke_a_loo-k_at → '테이커루컷'. a가 앞뒤 자음에 흡수됩니다." },
  ],
}
```

### 음원에 대해

기본은 브라우저 내장 TTS다. 즉시 동작하고 배속 조절이 되지만, **연음과 리듬은 실제 원어민 음성만큼 자연스럽지 않다.** 학습 효과를 최대로 하려면 문장별로 원어민 녹음을 `audioUrl` 에 연결하는 것을 권한다 — 코드 변경 없이 그대로 우선 사용된다.

macOS 기준 목소리는 Samantha 를 기본값으로 쓰고, Zarvox·Trinoids 같은 효과음 음성은 목록에서 제외했다.

## 브라우저 지원

Chrome / Edge / Safari 최신 버전. 섀도잉 녹음은 `MediaRecorder` 를 지원하지 않는 환경에서는 해당 블록이 자동으로 숨겨진다.

학습 기록과 가져온 코스는 브라우저 localStorage 에만 저장되며 외부로 전송되지 않는다. 유튜브 코스를 쓸 때만 `youtube.com` 에서 임베드 플레이어를 불러온다.
